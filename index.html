TNA animations for computing education

Where sequence data comes from, and what each source makes you decide before a transition network can be estimated. Five self-contained pages — no dependencies, no build step.

  • 3A · AUTOMATED ASSESSMENT
    Runs, submissions, and the edits in between

    A student edits, runs and submits in an online judge. The code visibly changes, but only the runs reach the log — then the edit states are recovered by comparing the code each run carried.

  • 3B · CODED DISCOURSE
    A student–AI conversation becomes states

    A turn is not a state until a codebook is applied to it. At the end, coding only the student collapses every assistant turn to a single AI.

  • 3C · OBSERVATION
    Where does one state end?

    Screen capture and think-aloud from a pair debugging a loop. One coder draws the segment boundaries; a second coder draws different ones from the same six minutes.

  • 3D · SENSORS
    Gaze becomes states only after someone draws the boxes

    Eye tracking over a spec, some code and a failing test. Raise the minimum dwell and the quick glances back at the error message stop existing.

  • 3E · BUILDING THE SEQUENCES
    actor, session, order, timestamp

    The same exercise as 3A, now across three students, two classes and two exercises — one flat log giving 3, 5 or 6 sequences depending on where the cuts go.

Every page shares the same controls: ← → to step, space to play or pause, a speed selector, and autoplay and loop toggles. Untick Autoplay to drive them by hand while presenting.

No student data appears in any of these files. Every identifier, timestamp and utterance is fabricated for the illustration.
